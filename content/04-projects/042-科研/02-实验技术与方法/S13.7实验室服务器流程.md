这四个脚本组成了一套**细菌基因组生信分析流程**的一部分。主要涵盖了：**基因组质量控制（QC）**、**抗性/毒力基因扫描（Abricate）**、**结果矩阵化**以及**最终结果汇总**。

以下是详细的对比表格和每个脚本的深度解析。

### 脚本详细解析

#### 1. `QC_V2.py` (基因组质量控制)

* **用途**：用于评估组装好的基因组质量。通常我们希望 N 50 较大，Contig 数量较少。
* **主要流程**：
1. 用户输入包含 `.fna` 文件的文件夹路径。
2. **GC 分析 (`analyze_genomes_gc`)**：读取序列，计算总长度和 G+C 碱基占比。
3. **N 50 分析 (`analyze_genomes_n50_contigs`)**：读取序列长度，排序并计算 N 50 值（代表组装连续性的指标）和 Contig 总数。
4. **合并**：将上述两步生成的临时 CSV (`genome_gc_...` 和 `genome_n50_...`) 按文件名合并，输出最终报告并删除中间文件。


* **注意**：脚本中写死识别 `.fna` 后缀，如果你的文件是 `.fasta`，需要修改代码中的 `if file.endswith(".fna"):`。

#### 2. `abricate_multi.sh` (抗性/毒力基因扫描)

* **用途**：利用 `abricate` 工具和 `GNU Parallel` 工具，对大量基因组进行高通量并行扫描。
* **主要流程**：
1. 定义输入输出路径（注意：脚本中路径是硬编码的 `/project/TBAMR03/...`，使用前必须修改）。
2. 创建输出目录：`3.resfinder_output` (抗性), `4.plasmidfinder_output` (质粒), `5.vfdb_output` (毒力)。
3. 定义函数 `process_fasta`：对单个文件运行 `abricate`，参数设定为最小识别度 90% (`--minid 90`) 和最小覆盖度 90% (`--mincov 90`)。
4. **并行执行**：使用 `parallel -j 100` 同时调用 100 个线程处理文件，极大地加快了分析速度。


* **依赖**：需要系统安装了 `abricate` 和 `parallel`。

#### 3. `Abricate_table_V2.py` (扫描结果矩阵化)

* **用途**：`abricate` 输出的是每个基因组一个文件，阅读不便。此脚本将文件夹内所有结果合并为一个大表格（矩阵）。
* **主要流程**：
1. 用户输入包含 abricate 结果（`.tabular` 或 `.txt`）的文件夹路径。
2. **构建基因库**：遍历所有文件，收集所有出现过的基因名称，建立一个去重后的总基因列表（Columns）。
3. **构建矩阵**：再次遍历文件，如果某菌株含有某基因，则在对应位置填入数量（通常为 1），否则为 0。
4. 输出 CSV 文件，行名为文件名（菌株名），列名为基因名。



#### 4. `csv_merge.sh` (数据清洗与最终合并)

* **用途**：这是一个“胶水”脚本，用于在最终汇总之前清洗数据格式。
* **主要流程**：
1. **处理 MLST 文件**：检查 `2.mlst.csv` 是否有表头，如果没有则添加一行标准的表头（file, species_type, ST, ...）。
2. **统一列名**：将目录下所有 `*output.csv` 的第一列列头强制修改为 `file`，确保合并时索引列一致。
3. **清洗 ID**：将第一列中的文件名后缀 `.tabular` 删掉，只保留菌株名，以便与其他表格（如 QC 结果）匹配。
4. **调用合并**：最后调用 `python /project/TBAMR03/0_EC/csv/csv_merge.py`（此脚本未提供，但推测是利用 Pandas 将清洗好的 CSV 按 `file` 列 merge 在一起）。



### 建议的操作流（Pipeline）

根据这些脚本的逻辑，一个合理的分析流程如下：

1. **准备数据**：将 `.fna` 基因组文件放入文件夹。
2. **质控**：运行 `QC_V2.py`，得到组装质量表。
3. **基因扫描**：修改并运行 `abricate_multi.sh`，生成原始的基因预测结果。
4. **矩阵化**：对上一步生成的三个输出文件夹（resfinder, plasmidfinder, vfdb）分别运行 `Abricate_table_V2.py`，得到三个矩阵 CSV 文件（例如命名为 `resfinder_output.csv` 等）。
5. **汇总**：将 QC 结果、MLST 结果（如有）、以及上一步生成的矩阵 CSV 放在同一目录下，运行 `csv_merge.sh` 得到最终的总表。
