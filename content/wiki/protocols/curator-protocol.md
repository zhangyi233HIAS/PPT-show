# 🎨 Curator 协议 — 知识库质量评估

> 知识库的"策展人"，负责评估文档质量、发现改进空间、生成优化建议。

## 概述

Curator 协议定义了系统化评估 Obsidian 知识库质量的标准和流程。它从**完整性、一致性、连通性、时效性**四个维度对知识库进行全面体检。

---

## 评估维度与评分标准

### 1. 完整性 (Completeness) — 权重 30%

评估文档内容的完备程度。

| 评分 | 标准 |
|------|------|
| 5 | 内容详尽，覆盖所有关键方面，有示例和参考 |
| 4 | 内容较完整，主要方面已覆盖 |
| 3 | 基本框架存在，但部分关键内容缺失 |
| 2 | 仅有大纲或部分内容 |
| 1 | 只有标题或极少量内容 |

**检查项：**
- [ ] 文档是否有清晰的结构（标题、小节）
- [ ] 关键概念是否有解释
- [ ] 是否包含实际案例或示例
- [ ] 是否有参考来源或链接

### 2. 一致性 (Consistency) — 权重 25%

评估术语、格式、风格的统一程度。

| 评分 | 标准 |
|------|------|
| 5 | 术语、格式、标签完全统一 |
| 4 | 基本统一，少量不一致 |
| 3 | 存在明显不一致但不影响理解 |
| 2 | 多处不一致，影响阅读体验 |
| 1 | 混乱无序，缺乏统一标准 |

**检查项：**
- [ ] 标签命名是否遵循统一规范
- [ ] 文件命名是否一致
- [ ] 日期格式是否统一
- [ ] 同一概念是否使用相同术语

### 3. 连通性 (Connectivity) — 权重 25%

评估文档间的链接和引用关系。

| 评分 | 标准 |
|------|------|
| 5 | 双向链接丰富，形成密集知识网络 |
| 4 | 大部分相关文档已互链 |
| 3 | 有基本链接，但存在孤立节点 |
| 2 | 链接稀疏，大量文档孤立 |
| 1 | 几乎没有内部链接 |

**检查项：**
- [ ] 孤立文件数量（无入链也无出链）
- [ ] 平均每篇文档的 wikilink 数量
- [ ] 是否存在断链（指向不存在的页面）
- [ ] MOC（Map of Content）覆盖率

### 4. 时效性 (Freshness) — 权重 20%

评估内容的新鲜度和维护状态。

| 评分 | 标准 |
|------|------|
| 5 | 最近 7 天内更新，内容反映最新状态 |
| 4 | 最近 30 天内更新 |
| 3 | 最近 90 天内更新 |
| 2 | 超过 90 天未更新 |
| 1 | 超过 180 天未更新或内容明显过时 |

## 评分流程

### 步骤一：数据采集

```
1. 扫描知识库目录结构
2. 统计文件数量、大小、修改时间
3. 提取所有 wikilink 和反向链接
4. 解析标签分布
5. 生成原始数据报告
```

### 步骤二：维度评分

```
1. 按四个维度逐文件评分
2. 计算各维度加权平均分
3. 识别低分文件（< 3.0）
4. 标记孤立文件和断链
```

### 步骤三：生成报告

```
1. 计算知识库总分（加权平均）
2. 按维度生成雷达图数据
3. 列出 Top 10 待改进文件
4. 生成具体优化建议
```

### 步骤四：优化建议

针对每个低分文件生成具体建议：

- **完整性不足** → 建议补充的具体内容
- **一致性问题** → 列出需统一的术语/格式
- **连通性差** → 建议添加的链接目标
- **时效性低** → 标记需要更新的内容

## 总分等级

| 总分范围 | 等级 | 含义 |
|----------|------|------|
| 4.5 - 5.0 | 🏆 卓越 | 知识库状态优秀 |
| 3.5 - 4.4 | ✅ 良好 | 基本完善，有改进空间 |
| 2.5 - 3.4 | ⚠️ 一般 | 需要系统性改进 |
| 1.5 - 2.4 | 🔶 较差 | 存在较多问题 |
| 1.0 - 1.4 | 🔴 严重 | 需要大规模重构 |

- **事件触发**：大批量文件变更后自动执行
