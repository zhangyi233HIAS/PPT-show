# 🧬 自我进化协议 — 知识库自动优化

> 让知识库具备自我诊断、自我修复、自我进化的能力，持续提升信息质量和可用性。

## 概述

自我进化协议（Evolution Protocol）是驱动整个知识库持续改进的核心引擎。它定义了自动化的监控、评估和优化流程，确保知识库随着时间推移变得越来越好。

## 模块一：监控 (Monitor)

### 1.1 索引健康监控

持续跟踪知识库的索引状态。

**监控指标：**
| 指标 | 正常范围 | 检查频率 |
|------|----------|----------|
| 文件总数 | ±10% 周环比 | 每日 |
| 链接总数 | 稳定增长 | 每日 |
| 孤立文件数 | < 总文件的 5% | 每周 |
| 断链数 | 0 | 每日 |
| 标签覆盖文件比 | > 80% | 每周 |
| 平均文件大小 | 1-10 KB | 每月 |

**监控方式：**
```
1. 每日自动扫描知识库目录
2. 提取文件元数据（大小、修改时间、链接数）
3. 对比历史数据，检测异常变化
4. 生成监控摘要
```

### 1.2 内容时效监控

跟踪内容的新鲜度。

**监控规则：**
```
- 核心文档（README、协议）：超过 30 天未更新 → ⚠️ 告警
- 项目文档：超过 14 天未更新 → ⚠️ 提醒
- 研究笔记：超过 60 天未更新 → 📋 待审
- 参考资料：超过 180 天未更新 → 🔍 验证时效
```

### 1.3 质量趋势监控

追踪知识库质量评分的变化趋势。

```
数据来源：[[curator-protocol]] 的定期评估结果
监控方式：
- 记录每次 Curator 评估的总分和各维度分
- 绘制质量趋势图
- 识别下降趋势并告警
```

## 模块二：诊断 (Diagnose)

### 2.1 问题分类

| 问题类型 | 严重级别 | 典型表现 |
|----------|----------|----------|
| 🔴 结构性问题 | 高 | 目录混乱、命名不一致 |
| 🟠 内容缺失 | 中 | 关键文档为空或过简 |
| 🟡 链接问题 | 中 | 断链、孤立文件 |
| 🟢 格式问题 | 低 | 格式不统一、标签不规范 |

### 2.2 诊断流程

```
1. 汇总监控模块的告警
2. 按严重级别排序
3. 分析问题根因
4. 评估修复优先级
5. 生成诊断报告
```

---

## 模块三：修复 (Repair)

### 3.1 自动修复（无需人工确认）

| 修复操作 | 触发条件 | 安全级别 |
|----------|----------|----------|
| 修复断链 | wikilink 指向已移动的文件 | 🟢 安全 |
| 补充标签 | 文件无任何标签 | 🟢 安全 |
| 更新索引 | 新增/删除文件后 | 🟢 安全 |
| 格式规范化 | 日期/标题格式不一致 | 🟢 安全 |

### 3.2 建议修复（需人工确认）

| 修复操作 | 触发条件 | 说明 |
|----------|----------|------|
| 补充内容 | 文件内容 < 100 字 | 提供补充建议 |
| 合并文件 | 高度相似的文件 | 提供合并方案 |
| 重组目录 | 目录结构不合理 | 提供重构方案 |
| 删除过时内容 | 确认已失效的信息 | 标记待删除 |

### 3.3 执行规则

```
安全原则：
1. 自动修复只做"无害"的操作
2. 可能影响内容的修改必须人工确认
3. 所有修复操作记录日志
4. 保留修复前的备份
```

---

## 模块四：验证 (Validate)

### 4.1 验证流程

```
1. 修复后重新运行监控
2. 对比修复前后的指标变化
3. 确认问题已解决
4. 检查是否引入新问题
```

### 4.2 验证指标

- 修复成功率（目标 > 95%）
- 回归率（修复后问题复发 < 5%）
- 副作用率（修复引入新问题 < 2%）
